# 第四阶段：浏览器演示与使用体验验收

验收日期：2026-09-21。

## 阶段目标

本阶段不增加中间件，重点验证一个个人开发者能否从浏览器完成项目配置、真实模型规划、受控执行和报告查看，并让页面准确表达当前轻量运行模式及失败后的处理方式。

## 已完成改进

- 系统概览返回当前对话模型名称，但不暴露模型密钥；页面显示实际的 `deepseek-flash` 和轻量/知识库模式。
- 轻量模式的首页链路改为 OpenAPI Schema 证据，不再固定展示 Qdrant、MinIO 或 RAG。
- Agent 表单增加初始变量 JSON，可用于账号、密码和业务预期值；提交后由服务端加密保存，页面清空输入。
- 固定计划 JSON 明确标记为 Stub 离线调试入口，避免与真实模型主链路混淆。
- 写操作确认显示 HTTP 方法、路径、计划哈希摘要及失效时间，并在提交确认时禁止重复点击。
- 任务状态统一使用中文；失败信息根据写入结果未知、超时、变量、OpenAPI 和确认版本问题给出处理建议。
- 取消、启动与确认按钮增加提交中状态；Toast 增加 `status`/`alert` 语义。
- 增加键盘焦点样式、禁用态和减少动画偏好；修复长任务目标导致的桌面横向溢出。
- 报告页在轻量模式显示 OpenAPI 规划依据，不再把空文档证据描述为 RAG 效果。
- 概览成功指标改为当前项目终态任务完成率，失败任务不会因未生成报告而被统计遗漏。

## 真实浏览器链路

使用浏览器创建长期保留的 `luminous-demo` 项目，导入 Luminous 实际 OpenAPI，共解析 39 个接口，环境为本机开发服务，只允许 GET、POST。

### 模糊目标失败样本（修复前历史记录）

目标为“查询最新帖子列表，验证接口返回 200，并检查响应中包含帖子列表数据”。真实模型错误选择了 `GET /api/bookmarks`，断言失败，任务终止。

这个结果暴露了旧版候选截取规则的缺陷。第五阶段已经增加确定性候选排序，并用同一目标复测通过；修复原因和前后证据见[第五阶段验收](phase5-agent-quality.md)。该样本仍保留，用来说明“模型提出计划，程序验证结果”的边界。

### 明确约束成功样本

目标为“只调用 OpenAPI 已声明的 GET /api/posts，验证 HTTP 状态码为 200；不要调用其他路径，不添加响应体断言”。

| 指标 | 结果 |
| --- | --- |
| 模型 | `deepseek-flash` |
| 任务 ID | `2101915347496992770` |
| 计划 | 1 步，`GET /api/posts` |
| 断言 | 1/1 通过 |
| 模型调用 | 4,201 Tokens，1,112 ms |
| HTTP 工具调用 | 成功，工具轨迹耗时 72 ms |
| 最终产物 | 持久化报告、脱敏请求响应、Markdown 与 JUnit XML 导出入口 |

以上是一次本机验收记录，不代表稳定性能指标或通用模型成功率。

## 当时仍然存在的真实限制

- 模糊目标曾因候选截取缺陷选错语义相近接口；第五阶段已降低该风险，但自然语言映射仍不是确定性保证。
- 初始变量编辑器是 JSON 输入，不是面向非技术用户的凭证表单；它适合当前个人开发者定位。
- 浏览器验收覆盖了项目创建、成功和失败任务、事件流与报告；本阶段没有再执行会产生业务写入的确认链路，写操作确认与恢复能力沿用前三阶段的自动化和真实故障验证。
- 当前仍依赖 MySQL，不是单文件应用；知识库模式仍需额外基础设施。
