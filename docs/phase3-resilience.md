# 第三阶段：取消、超时、重启与真实网络故障

日期：2026-09-21。真实模型使用官方 `deepseek-flash`，业务目标为已获授权的 luminous-dev。每个任务由模型生成四步计划：登录、查询当前用户、创建帖子、查询详情。脚本核对接口白名单及步骤顺序后才批准。

## 实现与取舍

- **步骤级停止检查**：取消和任务截止时间检查传入执行器，在每个 HTTP 步骤和每次重试前读取持久化状态；模型规划结束、执行结果返回及提交成功前也检查。数据库终态更新加条件，避免迟到线程将取消状态覆盖回执行中。
- **关闭透明重试**：关闭 Reactor Netty 自动重发，重试统一由业务策略判断。GET/HEAD 可有限重试，结果不确定的写请求停止。
- **时间预算一致**：默认任务总墙钟预算 15 分钟，包含人工等待；确认最多 10 分钟，且不能晚于任务截止时间。待确认过期由周期扫描结束，不依赖用户再次点击。
- **周期恢复**：启动及每 5 秒扫描最多 50 个可领取任务，等租约到期再恢复；排队任务在本实例去重。未到期的待确认任务不占恢复批次，批准或修改时按持久化引用恢复原始上下文。
- **明确失败**：上下文缺失、无法解密或没有可恢复计划时进入失败，不再无限挂起。领取旧任务后，将遗留 RUNNING 工具记录标记为 `AGENT_INTERRUPTED`，后续恢复以步骤审计为准。
- **稳定本地主密钥**：Windows 启动脚本未收到 `SECRET_STORE_MASTER_KEY` 时，生成并用当前用户 DPAPI 加密保存到 `.local-notes/secret-store-master-key.dpapi`，后续读取同一份。目录被 Git 忽略；这里只保存运行时加密主密钥，不复制 DeepSeek API Key。

## 真实故障验收

本轮使用只监听本机的 HTTP 代理连接真实业务沙箱，在收到真实响应后延迟或断开连接；通过强制终止脚本自己的 Java 子进程注入崩溃。未用 Mock 替代网络故障或模型调用。

| 场景 | 故障位置 | 实测结果 | 证据标识 |
| --- | --- | --- | --- |
| drop-write | 创建已成功，直接断开客户端连接 | FAILED，执行记录 EXECUTOR_409_003；只收到 1 次创建，数据库 1 条帖子 | 5c06e85cab |
| cancel-read | 当前用户 GET 暂不返回，此时取消 | CANCELLED；没有后续创建请求，0 条帖子 | 24776fcb2b |
| deadline-read | GET 延迟至 12 秒总预算耗尽 | FAILED，AGENT_408_001；没有后续创建请求，0 条帖子 | 6b8521ca45 |
| confirmation-expiry | 不批准计划，确认有效期 3 秒 | FAILED，AGENT_409_002；没有 HTTP 请求、没有帖子 | d67c4b3e79 |
| restart-waiting | 待确认时终止，同主密钥重启再批准 | SUCCEEDED；原计划可执行，创建 1 条帖子 | 443fb10498 |
| restart-read | 创建成功已持久化，最终 GET 未返回时终止 | 租约到期后恢复成功，只补做读取，仍仅 1 次创建 | f358feec7a |
| restart-write | 服务端已创建，Java 尚未收到响应并保存成功时终止 | 租约到期后 FAILED，执行记录 EXECUTOR_409_003；不重发写请求，1 条帖子 | 33b735456e |
| restart-wrong-key | 待确认时终止，换主密钥重启再批准 | FAILED，AGENT_409_005；没有 HTTP 请求、没有帖子 | a7464e8604 |

八个固定场景各一次均符合预期，全部专属账号、帖子、社区和相关缓存清理成功。正确结果可能是 FAILED，不能解释为业务任务全部成功。没有修改生产数据或停止共享基础设施。

增加恢复排队去重后，对最终产物再次运行 restart-read（标识 `a0b4dc6782`）通过。因此本轮共 9 次真实任务运行，覆盖 8 类场景；终态任务均无遗留 RUNNING 工具记录。这些是固定小样本，不发布泛化成功率。

最终 `mvn -o package`：84 项测试，0 失败、0 错误、0 跳过。新增确定性测试覆盖取消后不发下一步、取消后不重试、过期不发请求、恢复原始上下文、缺失上下文明确失败，以及恢复排队去重。Python 编译、PowerShell 语法与差异空白检查通过。Windows 启动脚本两次启动复用同一份受保护主密钥文件；本轮未运行完整浏览器端到端套件。

证据在 `output/resilience/<场景>-<标识>/result.json`，同目录 `app-*.log` 为测试进程日志。记录包含 OpenAPI 哈希、后端镜像、脱敏计划与工具轨迹、模型用量、代理请求次数和独立业务核验结果；`output` 不进入 Git。

夹具具有唯一 `[E2E_TEST]` 标记。独立按账号查询数据库数量，再请求业务详情核验标题、正文和作者；代理计数证明是否发送过重复创建请求。脚本最终先停止自己的客户端并等代理处理结束，再清理夹具，避免清理与写入竞争。本轮未遇到模型额度不足。

## 复现

恢复扫描使用同一个 dochelper 数据库，评测时不要同时启动其他恢复实例，否则不同主密钥的实例会竞争领取任务。脚本检查默认 18081 开发端口，发现占用就停止，不接管已有进程。先退出自己的开发实例，保持共享 MySQL 与 luminous-dev 正常运行。

```powershell
mvn package
$dockerExe = 'C:\Users\zx080\AppData\Local\Programs\DockerDesktop\resources\bin\docker.exe'
python scripts/evaluate_resilience.py --docker $dockerExe --key-file '<外部 API 密钥文件绝对路径>' --scenario all
```

脚本在 18082 启动 Java 子进程，使用 `local,deepseek,lightweight`。普通测试总预算 150 秒、确认 120 秒，特定场景分别缩短至 12 秒和 3 秒；HTTP 超时 20 秒，恢复扫描 1 秒，数据库租约 30 秒。每个场景内部保持主密钥稳定，只有 wrong-key 场景主动换密钥。重启后可能需要等待剩余租约，不应把尚未立即执行误判为卡死。

单独复现时将 `all` 换为表中场景名。任一场景不符合预期或清理失败，脚本非零退出并保留证据。测试涉及接口定义出站、夹具写入和本机进程故障，不可改成生产目标后直接运行。

正常开发使用：

```powershell
./scripts/start-real-local.ps1 -KeyFile '<外部 API 密钥文件绝对路径>' -Port 18081
```

显式主密钥环境变量优先。DPAPI 文件绑定当前 Windows 用户环境，换用户或机器不能假定可直接解密；解密失败应恢复正确主密钥，脚本不覆盖旧文件。过去使用临时密钥生成的旧密文不会自动恢复。裸 Java 与容器仍需显式配置稳定主密钥。

## API 与边界

`POST /api/v1/projects/{projectId}/agent-tasks/{taskId}/cancellation` 无请求体，HTTP 202 返回统一任务响应 `{code,message,data,requestId,timestamp}`。执行中的任务先设置 `cancelRequested=true`，到检查点后转为 CANCELLED；取消终态任务仍为 HTTP 409。确认接口格式不变，超过任务总截止时间拒绝批准。详情中的 `deadlineAt` 和 `confirmation.expiresAt` 表示两种截止时间。

任务取消为 `AGENT_CANCELLED`，任务超时为 `AGENT_408_001`，确认过期为 `AGENT_409_002`，上下文不能安全恢复为 `AGENT_409_005`。写入不确定记录 `EXECUTOR_409_003`，任务顶层进入 `NEEDS_REVIEW` 并停止自动重放。

取消和截止时间是协作式控制，不能撤回已经发出的请求，也不是在截止瞬间强制打断全部模型或 HTTP I/O。执行中的请求受自身超时约束，返回后不继续后续步骤。外部副作用必须独立核验。

恢复只复用成功记录、请求指纹一致且敏感输出仍可解密的步骤；不确定写入保守停止。本轮没有证明任意崩溃时刻、报告生成中断恢复或多实例 fencing 的正确性，不承诺 exactly-once，也不定位为分布式调度平台。
