# ApiPilot 求职版实施与验收计划

更新日期：2026-09-21。

## 已确认定位

- 主要面向 Java 后端岗位，展示模型规划、受控工具执行、反馈决策及验证能力。
- 单用户本地工具，暂不建设多租户、分布式调度或完整测试平台。
- 被测项目为同级目录 `../luminous`。检查源码，并在用户授权的 luminous-dev 沙箱运行专属夹具；不修改该项目源码。
- Agent 联调、演示及效果评测使用真实模型，不以 stub 结果替代真实模型指标。
- 用户授权使用官方最新可用 Flash 模型。已核实 API model ID 为 `deepseek-flash`，Base URL 为 `https://api.deepseek.com`，当前官方对应 V4.1 Flash。密钥从用户指定的外部文件读取，不写入仓库或日志。额度不足时报告并暂停相关调用，不擅自换供应商。
- 确定性执行约束仍需单元测试；这类测试只证明程序行为，不计入模型效果。

## 第一阶段：建立真实基线

先核验服务身份、模型连通性及 OpenAPI，再运行固定任务。DocHelper 与 Luminous 默认端口均为 8080，联调时为 DocHelper 单独分配并检查空闲端口，不停止其他服务解决冲突。

仅在 Luminous 开发测试沙箱执行写入。不得向 luminous-prod、80/443/8088 演示入口或 33066 数据库运行自动测试。所有生成的测试数据按照被测项目要求标记 `[E2E_TEST]`，记录资源 ID，并在结束后精确清理；清理失败须报告。

首条候选链：使用专用测试账号登录，创建带唯一标记的帖子，提取帖子 ID，查询详情，验证标题、正文和作者。账号准备与资源清理作为夹具管理，不让模型任意操作既有用户数据。具体参数及预期响应以实际 OpenAPI、DTO 和独立查询结果为准。

| 场景 | 独立验收标准 |
| --- | --- |
| 登录并查询当前用户 | Token 能传递，返回用户与测试账号一致 |
| 登录、创建帖子、查询详情 | 返回资源 ID 可追踪，指定字段与输入一致 |
| 请求目录外接口或引用缺失变量 | 发出对应 HTTP 请求前拒绝，并说明原因 |
| 提取路径错误 | 若证据充分，允许有限修正并展示差异，否则停止询问 |
| 返回结果违反已确认业务断言 | 如实判定失败，不允许模型删除或放宽断言换取成功 |
| 写请求响应丢失 | 标记结果未知，不盲目重复写入；故障场景须在可控测试环境构造 |

## 第二阶段：受控 Agent 闭环

流程：目标与接口证据 → 结构化计划 → 目录、参数和依赖校验 → 写操作确认 → 工具执行 → 反馈分类 → 有限修正或终止 → 证据报告。

区分三类反馈：

1. 可修正：有证据支持的参数或提取错误，限未完成步骤并保留修改差异。
2. 需用户决定：缺少业务输入、增加写操作、变更目标环境或关键断言。
3. 必须停止：业务断言不满足、越界请求、写操作执行结果未知。

优先检查授权与计划版本绑定、业务断言保护、写操作重放及任务卡住问题。暂不承诺任意崩溃后的自动恢复或恰好一次执行。是否调整 Agent 框架以闭环需要为依据，不为框架标签重写。
