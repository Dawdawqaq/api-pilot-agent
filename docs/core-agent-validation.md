## 失败证据与修复原因

原始基线 `output/evaluation/baseline-1e47112643/result.json` 中，登录成功，发帖链路失败：模型猜测作者字段为 `$.data.authorUsername`，实际为 `$.data.author.username`。系统如实保留失败，没有自动放宽业务断言。

排查发现提示词传递了 Operation 的 `$ref`，却缺少对应 Schema 定义。因此新增候选接口的本地 Schema 引用闭包：按文档导入 ID 隔离同名定义、消除循环、限制数量，不访问外部引用。最终同一任务目标生成了正确字段路径；这支持本次修复有效，不证明能消除所有模型错误。

中间一轮 `schema-context-deed840574` 的 Agent 断言通过，但验收脚本按列表查询计数得到 0。该轮不计入最终通过结果。最终验收改为按专属账号查询数据库资源 ID，再独立查询详情，避免列表可见性、分页或服务镜像差异干扰重复写入检查。

故障修复轨迹：

1. 真实模型生成发帖计划，待确认时通过修改接口添加 `verifiedTitle → $.missingTitle`。
2. 用户审阅的计划哈希随修改更新，批准的是新计划。
3. 登录、发帖成功，最后 GET 提取失败，返回 `EXECUTOR_422_002`。
4. 模型依据原计划、已完成步骤、错误信息和 Schema 修正提取路径；程序验证已完成步骤、接口、断言、提取变量名称均未被篡改。
5. 再次确认后，执行器按规范化请求指纹复用前两步，恢复令牌与帖子 ID，只重新执行 GET；独立核验只有一条帖子，提取标题正确。

## 确定性验证

`mvn -o package` 成功，75 项单元测试，0 失败、0 错误、0 跳过。覆盖本轮的重要约束：

- 计划修改与运行上下文一致；持久化失败保留原计划；脱敏展示不污染实际执行数据。
- 旧计划哈希拒绝确认；先释放确认租约再提交执行，避免领取失败后任务卡住。
- 自动修复不能改预期值、删断言、换接口、删提取器或修改已成功步骤。
- 任一步引用缺失变量、覆盖初始变量或引用目录外接口时，在前面的写步骤发出前拒绝整条链。
- 写请求超时，即便携带 `Idempotency-Key` 也只发一次；写响应后提取失败要求核验副作用。

这些使用桩和 Mock 验证 Java 约束，不计入真实模型评测。另已通过 Python 编译检查、JavaScript 语法检查和 `git diff --check`。真实应用健康检查为 UP，MySQL、Qdrant、MinIO 正常，无 Redis 健康依赖。本轮没有运行完整历史 `PublicInfrastructureIT` 或浏览器端到端套件。

## 复现

1. 启动已有共享基础设施及隔离的 luminous-dev，确认被测端口是 8080。脚本校验容器 Compose 标签与端口；不符合就停止。不要指向生产入口。
2. 构建并启动 ApiPilot。持久化主密钥需提前设置；未设置时启动脚本生成临时密钥，重启不能恢复旧运行上下文。

```powershell
mvn package
./scripts/start-real-local.ps1 -KeyFile '<外部密钥文件绝对路径>' -Port 18081
```

3. 待 `output/app.log` 显示启动成功后运行真实评测。脚本会创建专属夹具、自动审核限定接口的测试计划、核验业务状态并清理；不可把此自动批准方式用于真实业务数据。

## 本轮接口变更

接口前缀：`/api/v1/projects/{projectId}/agent-tasks/{taskId}`。ID 为路径参数。

| 方法与路径 | 参数 | 成功返回 | 主要异常 |
| --- | --- | --- | --- |
| GET 前缀 | 无请求体 | 任务详情，`data.confirmation.planHash` 为当前计划摘要 | 任务不存在 404 |
| POST 前缀 `/modify` | JSON `instruction`，修改指令 | 修改后的任务及新的确认摘要 | 非待确认、已决策或已重规划为 409；忙碌 409；修改次数上限 429；规划不合法 400/422 |
| POST 前缀 `/confirmation` | JSON `approved` 必填布尔值、`note` 可选最长 500 字、`planHash` 必填 64 位小写十六进制 | 当前任务详情，批准后异步执行 | 格式错误 400；旧哈希或已处理 409；确认过期 409；任务不存在 404 |

统一响应为 `{code,message,data,requestId,timestamp}`。成功 `code=SUCCESS`；错误时 `data=null`。旧客户端必须先 GET 获取并展示当前计划，提交所审阅的 `planHash`，不能在用户点击批准后静默刷新哈希代替审阅。前端已同步更新。

执行记录出现 `EXECUTOR_409_003` 表示写请求可能已生效，必须核验远端结果，禁止自动重放。任务顶层现在进入 `NEEDS_REVIEW`，事件流和报告均保留原始执行错误。

## 尚未完成的能力

- 移除了无业务用途的 Redis 依赖，但仍需 MySQL、Qdrant、MinIO；可选知识库与本地文件存储留待后续轻量化。
- 没有多用户鉴权隔离，不宜开放给不可信网络；模型约束不等于执行沙箱。
- 不承诺恰好一次执行；写操作不确定时以停止换取安全，需要人工处理业务副作用。
- 取消发生在编排检查点，不能撤回已发出的请求；重启恢复依赖稳定主密钥、未过期上下文及持久化结果，尚未验证任意时刻崩溃。
- 候选接口选择已加入中英文概念与操作意图归一化，并通过固定 50 条样本回归；数据集仍不能代表开放域业务 API。
- 自动修复锁定断言意味着原始断言本身写错时也会停止；必须由人调整目标或重新确认，不能让模型修改验收标准。
